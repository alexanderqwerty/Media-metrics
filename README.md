# АС «МедиаМетрика»

Автоматизированная система сбора и консолидации метрик медиаконтента


## 🎯 Цель лабораторной работы №3
Настройка системы контроля версий и подготовка инфраструктуры проекта:
1. Хранение UML-моделей (PlantUML) в репозитории наравне с исходным кодом.
2. Организация структуры проекта для последующей генерации кода и рефакторинга.
3. Подготовка конфигураций для развёртывания (Docker Compose, архитектура `linux/arm64`).

## 📂 Структура репозитория (планируемая)
## Описание
Система предназначена для автоматического периодического сбора показателей видеопубликаций с площадок VK, YouTube, TikTok, Rutube, Telegram и MAX, и передачи их в Twenty CRM (self-hosted). Решает проблему отсутствия единого документа для подтверждения объёма и результативности работы подразделения медиапроизводства вуза.

## Стек технологий
- **Язык:** Python 3.11+
- **Контейнеризация:** Docker / Docker Compose (образы `linux/arm64`)
- **База данных:** PostgreSQL 15+
- **CRM-система:** Twenty CRM (self-hosted, REST/GraphQL API)
- **ОС сервера:** Debian GNU/Linux (Raspberry Pi OS, aarch64)

## Поддерживаемые площадки и собираемые метрики
| Площадка | Извлекаемые показатели |
|----------|------------------------|
| VK | просмотры, лайки, комментарии, репосты |
| YouTube | просмотры, лайки, комментарии |
| TikTok | просмотры, лайки, комментарии, репосты |
| Rutube | просмотры, лайки, комментарии |
| Telegram | просмотры, реакции, пересылки |
| MAX | просмотры, реакции |

## Особенности архитектуры
- Сбор данных путём парсинга HTML-страниц (и API, где доступно).
- Идемпотентность записи в Twenty CRM (исключение дубликатов при повторном запуске).
- Изоляция отказов: сбой парсинга одной площадки не останавливает остальные.
- Соблюдение 152-ФЗ: тексты комментариев и персональные данные не сохраняются, собираются только количественные показатели.
